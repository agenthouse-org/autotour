# Webtour integration: preliminary assessment

This is a preliminary working assessment, not the complete commit-bound agenthouse feasibility bundle or approval. AutoTour was inspected at `df29fee8ac32920a133e9ec96243f6170e4e5877`; webtour was inspected at `658fad6a01db3ccf720ef10418fafb00169bccb3` plus its uncommitted working tree. The latter includes changes to waiting, placement, coachmarks, localization, schema, demo and tests. The copied runtime uses that working tree; its changes must be reviewed and preserved in a reproducible source revision before release.

Webtour provides browser custom elements, catalog and localization, preferences, live step execution, placement, schema and MCP authoring. AutoTour provides Node capture, screenshots, replay, video, review, publishing and regeneration. Their definitions have different purposes and are not interchangeable. A browser-only package avoids shipping Playwright to consumers while allowing one source repository. Existing runtime API, elements, event names, CSS contracts, schemas, storage keys and MCP tools are compatibility boundaries.

DealDesk is a known consumer. Its package.json points to a sibling checkout and its production website serves a checked-in vendor tree, with static routes, template imports, help integration and tests referencing webtour. A dependency change alone does not update production assets. Unknown external consumers and registry permissions have not been inventoried. Both proposed scoped package names returned public npm 404 during initial checks; this does not prove publishing rights or that private packages do not exist.

A big-bang rename makes cutover simple but risks breaking existing applications. Maintaining two independent repositories duplicates fixes. The proposed staged adapter keeps one source, distributes a lightweight runtime and compatibility bridge, migrates DealDesk after publication, then retires the old repository. Publishing, asset updates and consumer verification must happen in that order. A rollback restores the old dependency and vendor tree; storage keys remain unchanged. The old repository must not be archived before release and consumer checks succeed.

Remaining work: complete a commit-bound occurrence inventory and formal assessment, review the dirty webtour baseline, verify npm ownership and trusted publishing, test packed installations and live browser integration, migrate DealDesk, verify agent onboarding, publish packages and only then retire webtour. Enhancements beyond parity remain to be identified.
